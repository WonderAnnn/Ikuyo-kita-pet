# 喝水独立提醒手工测试（0.1.2）

## 目标

验证喝水提醒与有效工作提醒分开计时：喝水默认在北京时间 08:00–23:00 运行，每轮随机 15–20 分钟；它不依赖白名单前台应用或键鼠活动。暂停、锁屏和系统抑制期间不弹出，恢复后按窗口内经过的墙钟时间补发。

> 这是日常提醒功能，不是医疗建议。饮水量和间隔以医生意见、个人情况及系统设置为准。

## 前置准备

1. 构建并启动 `IkuyoPet.exe`，保留桌宠或在设置中关闭桌宠后使用系统通知。
2. 确认主页面“提醒规则”中存在一条类型为喝水/`water` 的规则，时间窗为 08:00–23:00，间隔范围为 15–20 分钟。
3. 为了快速测试，可临时把喝水规则的最小值和最大值都改为 1 分钟；测试结束后恢复 15–20 分钟。
4. 测试前打开日志页，记住当前喝水完成次数。

## 用例

### 1. 首次启动建立喝水周期

- 重启应用并等待一个提醒循环。
- 预期：不会立刻弹出喝水气泡；数据库中建立一个喝水运行周期。
- 预期：活动规则仍按有效前台工作秒数独立运行。

### 2. 喝水提醒展示

- 保持应用运行到测试间隔结束。
- 预期：桌宠出现语言气泡，文案包含“喝口水”，末尾带颜文字；选项为“好～我现在就喝！/等一下下嘛～/这次先跳过啦”。
- 关闭桌宠后重复测试，预期：改为安静的 Windows 系统通知，不弹出主页面。

### 3. 不依赖前台工作时间

- 在喝水周期内切换到不在白名单的应用，或停止键鼠操作；不要暂停提醒。
- 预期：达到墙钟间隔后仍会出现喝水提醒。
- 预期：该提醒不会增加有效工作秒数。

### 4. 完成、稍后、跳过和日志

- 分别点击“好～我现在就喝！”，以及在另外两轮测试中点击“等一下下嘛～”“这次先跳过啦”。
- 预期：气泡按现有 0.5 秒内渐变逻辑收起；完成、稍后、跳过分别写入喝水日志。
- 点击日志筛选，预期可按“喝水”查看这些记录；主页面喝水完成次数只统计完成结果。
- 完成后下一轮重新随机 15–20 分钟，不会沿用上一轮的目标秒数。

### 5. 暂停/锁屏/抑制恢复

- 在周期中途暂停提醒或锁屏 2 分钟，期间不应出现气泡或系统通知。
- 恢复后等待调度循环。
- 预期：按暂停/锁屏前后处于 08:00–23:00 窗口内的经过时间补算；达到目标时只出现一次提醒，不重复创建同一事件。

### 6. 时间窗边界

- 将系统时间或测试时钟置于 23:00 后，等待循环。
- 预期：不弹出喝水提醒；运行时保持待命。
- 在次日 08:00 后恢复。
- 预期：不把睡眠时段计入喝水周期，只从可提醒窗口继续计时。

## 自动化覆盖

- `WallClockReminderSchedulerTests`：15–20 分钟采样、墙钟到期、跨夜不计睡眠时间。
- `ReminderLoopTests.WaterRuleUsesWallClockAndIgnoresActiveWorkSamples`：提醒循环不消费前台工作样本，仍按墙钟触发。
- `ReminderActionCoordinatorTests.WaterActionStartsTheNextWallClockCycle`：喝水操作后运行时正确重置。

## 失败记录

记录测试日期、版本、是否使用桌宠、规则参数、当前时区、预期与实际提醒时间，以及日志页中的事件结果；不要把医疗报告或窗口内容提交到仓库。
