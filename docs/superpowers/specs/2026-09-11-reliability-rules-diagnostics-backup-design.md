# Ikuyo Pet 可靠性升级：规则设置、状态诊断与数据备份规格

> 状态：已实现，测试通过（266/266）。
> 日期：2026-09-11

## 1. 目标与边界

本规格覆盖三项可靠性优先的能力，不改变第一阶段的离线与隐私边界：

1. **提醒规则可配置**——喝水间隔、活动间隔、建议活动时长、生效时段、免打扰时段、启用开关和提醒文案全部可在界面中修改；医生给出新建议后只改参数，不改代码。
2. **状态诊断面板**——回答“为什么没有计时 / 为什么没有提醒”：当前前台是否在白名单、本轮已累计多少有效工作、下一次喝水/活动预计时间、以及具体原因列表。
3. **数据备份与恢复**——每天首次启动自动备份 SQLite 数据库、可配置保留份数、手动备份/恢复（含恢复前安全副本）、全部数据 JSON 导出。

不引入新的网络行为、新的系统权限或新的个人数据类别。备份、导出文件均保存在本机。

## 2. 提醒规则设置

### 2.1 数据与流程

- 现有 `reminder_rules` 表已含全部所需字段（间隔区间、活动时长、生效时段、免打扰时段、启用、参数来源与版本），不新增迁移。
- 新增 `ReminderRuleDraft`（Core）：编辑用字符串草稿，负责 `HH:mm` 与分钟数解析、范围校验（间隔 1–720 分钟、活动时长 1–240 分钟、起止不得相同、min ≤ max、喝水规则不填活动时长），`Build()` 产出 `ParameterSource="user"` 的规则。
- 主窗口“提醒规则”页从只读摘要升级为两张可编辑卡片（喝水 / 活动），保存按钮校验两条草稿后整体落库；校验失败时不写库并显示原因。
- 提醒循环每 30 秒重读规则，保存后最多 30 秒内生效，无需重启。
- 固定默认规则 ID 抽为 `DefaultReminderRuleIds`（活动 / 喝水），循环、编辑器与诊断共用。

### 2.2 界面

- 喝水卡：启用、文案、生效起止、间隔区间（min–max）、免打扰开关与起止。
- 活动卡：启用、文案、生效起止、间隔区间、建议活动时长、免打扰开关与起止。
- 底部固定提示：时间格式、区间随机取值说明、“医生给出新建议后直接修改数值即可”。

## 3. 状态诊断面板

### 3.1 服务

新增 `StatusDiagnosticsService`（Core，`IkuyoPet.Core.Diagnostics`）：

- 输入：`IEventRepository`（规则、白名单、运行时状态）、`IActivityProbe`（前台采样）、时区、时间提供者、桌宠开关、暂停状态。
- 输出 `DiagnosticsReport`：呈现渠道、暂停状态、抑制状态（全屏/演示/锁屏）、工作计时状态（前台进程、可否累计、原因列表）、每条规则的状态（状态文本、下次预计文本、原因列表）。
- 工作原因覆盖：前台不在白名单（列出白名单）、锁屏、全屏、演示模式、空闲超过 5 分钟。
- 规则原因覆盖：已停用、不在生效时段（显示当前时间与时段）、免打扰时段、已到提醒时间、搁置等待重试（含重试时刻）、未响应已结束、累计进度（已计/目标/还差）与预计提醒时间。

### 3.2 界面

- 主窗口新增“状态诊断”导航页（枚举 `MainWindowPage.Diagnostics`）。
- 进入页面立即刷新一次，之后每 10 秒自动刷新一次（仅在该页可见时）。
- 三张卡片：提醒呈现（渠道/暂停/抑制）、有效工作计时（结论 + 原因列表）、提醒规则状态（每条规则一张小卡）。

## 4. 数据备份与恢复

### 4.1 服务

新增 `DataManagementService`（Infrastructure）：

- **备份**：`VACUUM INTO` 在线生成一致性副本，应用运行中可随时调用。
- **启动自动备份**：每天首次启动写入 `backups/ikuyo-pet-yyyyMMdd.db`（当天已有则跳过），按保留份数（1–365，默认 14，存于 `app_settings` 的 `backup.retention`）清理最旧的每日备份。
- **恢复**：先 `wal_checkpoint(TRUNCATE)` 并清空连接池，把当前库复制为 `pre-restore-时间戳.db` 安全副本，再用备份覆盖主库；由 App 层先停掉提醒与计时循环后调用，完成后重启进程。
- **全量导出**：六张表（reminder_rules、reminder_events、reminder_runtime_state、tracked_apps、work_sessions、app_settings）导出为带版本号的 JSON 文档，作为长期存档。

### 4.2 界面与接线

- 设置页新增“数据备份与恢复”卡片：备份目录展示、立即备份、恢复备份（选择文件 + 覆盖确认）、导出全部数据 JSON、打开备份文件夹、保留份数设置、最近备份列表。
- `App.OnStartup` 在数据库迁移后立即执行当天启动备份（失败仅记录调试日志，不阻断启动）。
- 恢复流程：界面确认 → `App.OnRestoreConfirmed` 停止两个后台循环 → `ApplyRestore` → 重启进程。

## 5. 测试

- `ReminderRuleDraftTests`：默认值构建、非法值校验文案、区间反转、喝水规则活动时长、时间/分钟解析边界、已有规则往返。
- `StatusDiagnosticsServiceTests`：白名单累计中、非白名单原因、锁屏/空闲原因、停用规则、生效时段外、免打扰、搁置/到时状态、暂停与渠道文本。
- `DataManagementServiceTests`：备份可读、每日一份与保留清理、保留份数读写与钳制、恢复替换与安全副本、拒绝缺失/自身目标、JSON 全表导出、安全副本不列入每日备份。
- `MainWindowViewModelRulesTests`：草稿从持久化规则初始化、保存落库（ParameterSource=user）、校验失败不落库。

## 6. 隐私与医疗边界

- 诊断面板只读取进程名、锁屏/全屏状态与空闲时长——均为现有计时条件，不新增数据收集。
- 备份与导出文件仅在本机；删除备份目录即可删除副本。
- 规则设置页保留“默认值不是诊断或治疗建议”的提示；参数来源标记（general-default / user）让用户能区分默认值与自己（或医生建议）修改过的值。
