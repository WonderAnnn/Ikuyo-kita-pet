# Ikuyo Pet 第一次完整闭环（方案 A）设计规格

> 状态：待用户书面审查
> 日期：2026-09-09
> 适用范围：第一阶段离线提醒、日志、可替换桌宠；不包含应用内 AI 生成工作室

## 1. 目标

在现有离线 MVP 骨架上完成一条可以真实运行和验收的闭环：当符合用户已确认条件的有效电脑工作累计达到本轮随机阈值时，透明桌宠以语言气泡建议离屏并轻缓活动；用户可在气泡内直接接受、延后或跳过；系统把显示、响应、重试与结果写入 SQLite，并在今日页和日志页中可见。桌宠关闭时，同一事件改由 Windows 通知呈现。

本闭环采用方案 A：每轮在 40–50 分钟内抽取一个整数阈值，按“有效电脑工作时间”累计，而不是单纯按墙上时间倒计时。默认建议活动 5 分钟。上述数值是保守的通用办公提醒配置，不是诊断、治疗方案或个体医嘱；医生或康复师给出的建议拥有最高优先级。

## 2. 当前基线与需要闭合的断点

2026-09-09 的 Release 基线为 0 警告、0 错误，现有 118 项自动化测试全部通过。代码已经具备 SQLite 仓储、提醒状态机、桌宠/通知路由、透明窗口、气泡动作、皮肤校验与导入、工作时间统计和系统托盘。

但现状尚不是可运行的完整闭环：

1. `PetWindow.SetSkinImage()` 已存在，应用启动时却没有加载当前皮肤，实际仍显示咖啡杯占位符。
2. 首次数据库没有默认提醒规则，应用不会自然产生第一条提醒。
3. `ReminderRule` 只有固定 `IntervalMinutes`，不支持 40–50 分钟区间，也没有持久化本轮随机阈值。
4. `snoozed` 和 `ShouldRetry` 已存在于模型中，但没有独立的重提调度；无响应也不会自动进入 `unanswered`。
5. 完成、延后和跳过的颜文字反馈已经定义，但点击后没有真正显示反馈气泡。
6. 真实 Windows 锁屏、全屏和演示状态尚未接入提醒抑制链路。
7. `app_settings` 表已存在，但桌宠开关和当前皮肤选择尚未持久化。

本规格只修复完成第一条真实闭环所需要的断点，不提前加入 AI、云同步、症状诊断或动作识别。

## 3. 用户透明 PNG 与等比显示

### 3.1 已验证素材事实

用户提供的 PNG 已验证为：

- 像素尺寸：406 × 996；
- 像素格式：BGRA 32 位；
- Alpha 范围：0–255，包含透明和半透明边缘；
- SHA-256：`4FE8F8AD6725E7B45BC67C683B277FC3F7FA9DA842312F40BD252339D861464C`；
- 无需抠图，不应重新擦除头发、衣服或鞋子边缘。

### 3.2 缩放规则

桌宠必须保持原始纵横比：

```text
aspect = 406 / 996 ≈ 0.4076305
scale  = min(160 / 406, 280 / 996) ≈ 0.2811245
renderedWidth  = 406 × scale ≈ 114.14 DIP
renderedHeight = 996 × scale = 280 DIP
```

WPF 图像区域使用最大 160 × 280 DIP、`Stretch="Uniform"`、水平居中和底部对齐。第一版实际角色显示约为 114 × 280 DIP。禁止使用 `Fill`、独立修改宽高、裁切腿脚或强行压成正方形。DPI 改变时按 DIP 布局，由 WPF 统一换算物理像素；原图只解码一次并冻结，不反复重采样。

桌宠窗口需要为竖版全身图增加高度，同时保持气泡宽度约 356 DIP。透明区域不得成为覆盖桌面的矩形点击层；命中测试只保留在角色非透明像素的可用近似区域和气泡交互区域。角色位置被拖动后应约束在当前显示器工作区内。

### 3.3 本机皮肤包

本机安装目录固定为：

```text
%LocalAppData%\IkuyoPet\skins\user.ikuyo-local\1.0.0\
  manifest.json
  idle.png
  remind.png
```

第一次闭环允许 `idle.png` 与 `remind.png` 使用同一张透明 PNG；这不会伪装成动画。`manifest.json` 使用原始画布尺寸 406 × 996、`fps = 1`。启动时先重新校验 manifest、PNG 容器、透明通道和实际尺寸；校验成功才调用 `SetSkinImage(idle.png)`，失败则保留可再分发占位皮肤并给出可诊断提示，不能导致应用退出。

当前皮肤只记录 `id`、`version` 和已安装目录，不把图片二进制写入 SQLite。提醒显示时使用 `remind.png`，提醒结束或反馈气泡消失后恢复 `idle.png`。

## 4. 图片版权与公开仓库门禁

### 4.1 当前默认策略

这张图可立即作为用户本机私有皮肤使用。图片来源文件名不能证明作者、许可或再分发权，因此在取得并记录明确许可之前，状态必须是：

```text
redistributionAllowed = false
license = "Personal local use; redistribution permission not established"
```

本机皮肤放在 `%LocalAppData%`，不复制到项目 `Content`、发布包或 Git 跟踪目录。

### 4.2 允许进入公开 Git 的条件

仅当能够记录下列信息时，才可另行把图片放入公开仓库：

- 原作者或合法权利来源；
- 原始来源 URL 或可验证的授权文件；
- 明确允许修改和公开再分发的许可范围；
- 是否允许商业使用，以及署名方式；
- 授权取得日期和证据副本。

满足条件后，为图片建立独立资产许可文件；MIT 只覆盖代码，不能覆盖第三方角色和画师作品。CI 应检查任何受跟踪皮肤目录都存在资产许可记录。

### 4.3 README 可以写什么

README 可以声明项目与动画官方、出版社、制作委员会和画师无隶属或背书关系，可以提供权利人联系与移除流程，也可以说明项目当前不接受与第三方角色素材相关的捐赠或赞助。但“非商业”“不接受捐赠”“如侵权即删除”都不能替代事先取得的复制和网络传播许可，也不能作为允许上传图片的依据。

如果后续收到可信权利通知，应从当前分支和发布包移除相关素材，停止新的分发，并用有明确许可的原创/占位皮肤替代。是否需要清理 Git 历史应根据托管平台要求和具体通知处理，不在自动脚本中执行破坏性历史重写。

## 5. 方案 A 的有效工作计时语义

本方案复用用户已经确认的有效工作定义。只有以下条件同时成立时才累计：

1. 当前前台进程属于用户启用的白名单，例如 `pycharm64`；
2. Windows 会话未锁屏；
3. 最近 5 分钟内存在系统级人机输入；
4. 当前采样与上一采样之间没有超过允许的采样缺口；
5. 应用未处于全局暂停提醒状态。

后台运行、切到非白名单程序、锁屏、离开电脑、系统睡眠和长采样缺口均不累计。该数据只能表述为“有效电脑工作时间”，不能表述为软件已经检测到用户持续坐着。

用于统计的采样与用于活动提醒的累计必须共享同一份有效时间增量，不能分别读取 Windows 状态后产生不一致。工作统计继续记录按应用划分的会话；活动提醒调度器只接收本轮新增的有效秒数，不读取窗口标题、文件名、项目名、键盘内容、鼠标轨迹或屏幕图像。

## 6. 随机 40–50 分钟调度

### 6.1 抽样与持久化

每轮开始时通过可注入、可测试的随机源，从闭区间 `[40, 50]` 抽取一个整数分钟数。抽样只发生一次，随后立即持久化；30 秒轮询期间不得反复抽样。

运行状态至少包含：

```text
rule_id
cycle_id
target_active_seconds
accumulated_active_seconds
state
attempt
retry_due_at
updated_at
```

应用重启后继续同一轮剩余有效工作时间，不重新抽取阈值，也不立即补发提醒。用户完成、跳过或达到无响应上限后结束当前轮，再抽取下一轮 40–50 分钟阈值并把累计值清零。

### 6.2 第一轮与跨日

首次启动创建一条启用的“离屏活动”默认规则，并开始累计，不在刚启动时立即提醒。跨日时不产生睡眠记录；若跨过静默时段或系统睡眠，保留尚未完成的有效工作累计，但休眠时间本身不计入。

默认静默时段只作为配置示例，不从用户睡眠数据推断。医生或用户后续调整规则只影响新一轮；当前轮若参数版本发生变化，应安全结束并按新版本开始，既有日志保持不可变。

## 7. 一次提醒的完整状态闭环

```text
累计有效工作达到本轮阈值
  ├─ 锁屏 / 全屏 / 演示 / 暂停中
  │    └─ 只保留一条 pending，不显示、不堆积；恢复有效桌面 2 分钟后再呈现
  └─ 可呈现
       ├─ 桌宠开启 → 透明桌宠气泡
       └─ 桌宠关闭 → Windows 安静通知
              │
              ├─ “好呀，我这就起来走走” → accepted/completed
              ├─ “再等我五分钟嘛”       → snoozed，5 分钟后重提
              ├─ “这次先让我略过吧”     → skipped
              └─ 无响应                  → 5 分钟后重提，总显示次数最多 3 次
                                               └─ 仍无响应 → unanswered
```

动作采用自然的句内加粗文字，不使用突兀按钮块。底层继续保留稳定枚举，界面显示语义如下：

| 底层结果 | 日志显示 | 行为 |
| --- | --- | --- |
| `Completed` | 已接受活动 | 结束本轮，显示完成反馈，再创建下一轮 |
| `Snoozed` | 已搁置 5 分钟 | 保留本轮，创建一次重提时间 |
| `Skipped` | 本次未进行 | 结束本轮，显示温和反馈，再创建下一轮 |
| `Unanswered` | 未响应 | 达到显示上限后结束本轮，再创建下一轮 |

软件不声称用户点击“接受”后已经完成了真实活动，也不使用摄像头、传感器或输入行为验证动作。日志记录的是提醒响应，而不是医学依从性。

反馈气泡每段最多一个颜文字，并放在句末：

- 接受：`ദ്ദി˶>𖥦<)✧`
- 搁置：`(,,•́ . •̀,,)`
- 跳过或无响应结束：`ʕ.•᷅ࡇ•᷄.ʔ`

反馈短暂显示后回到安静待机；重复点击通过事件状态的条件更新保持幂等，不能重复计数。

## 8. 默认活动建议与医学边界

第一次闭环默认文案建议“离开屏幕，在舒适范围内站起、轻缓走动或换姿势 5 分钟”。5 分钟来自职业健康资料的保守示例：英国 HSE 建议短而频繁的休息，示例为连续屏幕工作约 50–60 分钟后休息 5–10 分钟；CDC/NIOSH 资料提到在常规休息外加入每小时 5 分钟休息可降低电脑工作者的不适和视疲劳。WHO 建议成年人减少久坐并以任何强度的身体活动替代，但没有规定唯一的 40–50 分钟阈值。

因此：

- 40–50 分钟是用户选择的产品区间，与短而频繁的职业健康方向相容；随机化只用于降低机械感，没有独立医学获益声明。
- 5 分钟是可配置的通用办公默认值，不是针对腰椎间盘影像表现的处方。
- 医生意见到达前不内置弯腰、扭转、负重、深蹲、腰部拉伸等具体治疗动作。
- 活动应限制在舒适范围；若疼痛、麻木或无力出现或加重，应停止并咨询医生或康复师。
- 桌宠不得根据用户上传的检查图、报告或症状自动判断动作。

NICE 对腰痛/坐骨神经痛的建议强调根据个人需要和能力提供自我管理建议，并鼓励在合适范围内继续正常活动；NHS 对椎间盘突出相关建议也强调循序渐进的温和活动，前提是不引起或加重疼痛。这些内容只用于约束软件文案，不替代用户的医生意见。

医生方案允许覆盖以下参数，但不保存 MRI 或诊断原件：

```text
interval_min_minutes
interval_max_minutes
activity_duration_minutes
allowed_activity_text
avoid_activity_text
symptom_stop_text
snooze_minutes
max_attempts
effective_date
review_date
source = clinician | user | general-default
```

设置界面必须清楚标出“医生方案”和“通用默认”，医生方案优先级最高。历史提醒事件保存当时生效的建议时长与参数版本，规则修改不能改写过去日志。

## 9. 数据与组件边界

### 9.1 Core

- 扩展提醒规则为最小/最大间隔、活动建议时长和参数来源。
- 新增可测试的随机区间生成接口。
- 新增只接收有效工作秒数的活动提醒周期状态机。
- 保留现有 `ReminderOutcome` 兼容性，显示层把 `Completed` 映射为“已接受活动”。

### 9.2 Infrastructure

- SQLite 迁移保存规则区间、活动时长、参数版本和运行状态。
- Windows 活动探针补齐真实锁屏状态；全屏/演示检测作为独立可替换探针。
- 重提调度持久化，应用退出或重启不会丢失，也不会一次补发多条。

### 9.3 Pet

- 皮肤解析器根据当前选择加载 `idle.png` / `remind.png`。
- 竖版图始终按第 3.2 节公式等比显示。
- 动作反馈结束后恢复 idle；素材损坏时回退占位图。

### 9.4 App

- 首次启动只在规则表为空时写入方案 A 默认规则，不覆盖用户已有配置。
- 桌宠开关、当前皮肤和规则来源持久化。
- 动作完成后刷新今日摘要和日志，不要求重启或切换日期。

## 10. 故障处理

- 皮肤不存在、校验失败或解码失败：保留占位皮肤，提醒和日志继续工作。
- 桌宠渲染失败：同一提醒降级到 Windows 通知，并更新实际渠道。
- Windows 通知不可用：记录被抑制原因，不弹主窗口、不循环报错。
- SQLite 写入失败：不呈现无法追踪的提醒；保留诊断日志并在下一轮轮询重试。
- 随机源异常或配置越界：拒绝保存配置，继续使用上一份有效规则。
- 锁屏、全屏或长时间离开：停止有效时间累计，只保留最多一条待呈现提醒。

## 11. 测试与验收

### 11.1 自动化测试

1. PNG 406 × 996 在 160 × 280 容器中计算为约 114 × 280，宽高比误差不超过浮点容差。
2. 皮肤校验器检查真实 PNG 签名、透明通道、manifest 与图片实际尺寸一致。
3. 当前皮肤选择可持久化；路径越出 skins 根目录、资源缺失或 manifest 损坏时回退占位图。
4. 随机源边界测试覆盖 40、50 和中间值；每轮只抽样一次。
5. 非白名单、锁屏、空闲达到 5 分钟、长采样缺口和提醒暂停均不累计。
6. 应用重启后恢复累计值和已选阈值，不立即补发。
7. 接受、跳过、搁置、连续无响应分别进入正确状态；重提总显示次数最多 3 次。
8. 同一动作重复触发只写入一次最终结果。
9. 动作后今日页和日志页刷新，并保留推荐活动时长与参数版本快照。
10. 皮肤/桌宠失败时降级通知，数据库事件渠道与实际渠道一致。

### 11.2 手工验收

- 在 100%、125%、150% DPI 下，人物不横向拉伸、不裁脚，默认约 280 DIP 高。
- 透明区域不出现绿色/白色方框，拖动后仍位于当前显示器工作区。
- 将测试随机源固定为短阈值后，完成一次“累计 → 提醒 → 接受/搁置/跳过 → 反馈 → 日志刷新”的端到端闭环。
- 隐藏桌宠后，同一流程通过 Windows 通知完成。
- 锁屏、全屏和离开电脑期间不提醒、不累计；恢复后只出现一条待办。
- 退出并重新启动后，皮肤、桌宠开关、本轮随机阈值和累计进度保持一致。
- 在没有 MySQL、网络和管理员权限的普通 Windows 账户中运行。

## 12. 实施脉络

后续实现计划按以下顺序拆分，每个任务执行 TDD，并在完成后依次进行规格审查和代码质量审查：

1. 强化皮肤校验，建立本机皮肤选择和安全路径解析。
2. 将用户 PNG 安装为本机静态双状态皮肤，并完成等比桌宠布局。
3. 扩展规则与 SQLite 迁移，引入 40–50 分钟可测试随机区间和持久化周期状态。
4. 让工作跟踪共享有效秒数给活动调度器，补齐锁屏状态。
5. 接通接受、5 分钟搁置、跳过和最多三次无响应重提。
6. 接通结果反馈气泡、idle/remind 切换和今日/日志即时刷新。
7. 接入全屏/演示抑制、恢复延迟和通知降级。
8. 执行 Release 全量验证、真实 GUI 冒烟测试和公开资产边界检查。

## 13. 明确不在本闭环

- 应用内 AI 图片识别、背景移除、图像生成或在线上传。
- 摄像头、姿态识别、运动完成检测和症状采集。
- 睡眠记录、医疗报告解析、疾病评分或自动治疗建议。
- 云账号、跨设备同步、远程推送和排行榜。
- 在未确认再分发许可时，把用户角色图片加入公开 Git 或发布包。
