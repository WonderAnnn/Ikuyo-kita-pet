# Ikuyo Pet 初步设计规格

状态：已完成头脑风暴，等待用户审阅。

## 1. 产品目标

Ikuyo Pet 是一个面向 Windows 的个人健康提醒器。它常驻系统托盘，默认以透明、可拖动的桌宠轻提示用户喝水、起身活动和休息眼睛；桌宠关闭后自动切换为 Windows 原生通知。它在本机保存提醒响应和有效工作时长，帮助用户回顾自己的节奏，不提供诊断或治疗建议。

第一版必须在没有网络、没有 MySQL 服务、没有账号的情况下运行。第二阶段再增加“导入参考图并由 AI 生成桌宠皮肤”的在线工作室，生成结果通过标准皮肤包回到第一版的本地皮肤系统。

## 2. 已确认的范围

### 第一版包含

- 饮水、起身活动、休息眼睛等可编辑提醒规则。
- 默认桌宠模式（C）：透明背景、可拖动、约 160 px、普通桌面右下角出现。
- 关闭桌宠后切换为原生 Windows 通知模式（A），不打开主窗口、不抢键盘焦点。
- 通知动作：完成、稍后、跳过；动作可在通知本身完成。
- 无响应重试：默认 10 分钟后重提，最多三次，随后记为“未响应”。
- 锁屏、全屏或演示状态时隐藏桌宠和横幅；恢复普通桌面 2 分钟后再提示。
- SQLite 本地日志：计划时间、实际显示时间、渠道、动作时间、延后次数和最终结果。
- 工作时长统计：只对白名单应用累计前台有效时间。
- 本地皮肤导入和替换，支持 PNG/WebP 静态图和可选动画帧。
- 今日概览、提醒时间线、应用时长、桌宠管理、规则设置和数据导出界面。

### 第一版明确不包含

- 不记录睡眠开始、结束、时长、质量或睡眠阶段。夜间时段只作为静默条件。
- 不读取键盘内容、鼠标轨迹、窗口标题、文档内容、网页内容或屏幕截图。
- 不保存或解析用户的影像报告、体成分报告等医疗原件。
- 不做云同步、账号体系、跨设备同步或远程推送。
- 不在应用内调用生成式 AI。

## 3. 技术选型

### 推荐栈

- 语言：C#。
- 桌面 UI：WPF，目标框架为 .NET 10 LTS。当前机器已安装 .NET 9 SDK；正式开发时升级 .NET 10 SDK。
- Windows 能力：Windows App SDK 的 `Microsoft.Windows.AppNotifications` 用于本地交互通知；WPF 透明窗口承载桌宠。
- 托盘：`ITrayIconHost` 抽象，第一版采用成熟的 WPF 托盘实现，避免把 Shell 通知细节散落在业务代码中。
- 本地数据库：SQLite，使用参数化 SQL 或轻量数据访问层；数据库文件保存在 `%LocalAppData%\\IkuyoPet\\ikuyo-pet.db`。
- 皮肤目录：`%LocalAppData%\\IkuyoPet\\skins\\<skin-id>\\`，不与安装目录混写。
- 测试：xUnit，核心状态机和时间计算使用纯单元测试；Windows 适配层使用少量手工验收测试。
- 开发工具根目录：`G:\IkuyoPetDev\`；.NET SDK、NuGet 缓存和可选 SQLite CLI 分别位于 `dotnet\`、`nuget\packages\` 和 `tools\sqlite\`。

SQLite 是嵌入式数据库，应用随包携带运行库即可，不需要 MySQL、端口、服务、账号或管理员权限。开源用户安装后直接得到一个本地数据库文件；应用提供 CSV 导出和数据库备份入口。

### 目标模块边界

```text
IkuyoPet.App                 WPF 启动、窗口、导航、依赖注入
IkuyoPet.Core                提醒规则、状态机、工作会话、皮肤契约
IkuyoPet.Infrastructure     SQLite、Windows App SDK、前台/锁屏检测、托盘
IkuyoPet.Pet                 透明桌宠窗口、动画、拖动、气泡
IkuyoPet.Core.Tests                Core 单元测试和集成测试夹具
assets/skins/default         原创占位皮肤（不含第三方角色素材）
```

`ReminderEngine` 不知道提醒是由桌宠还是通知呈现；它只发出待呈现事件并接收用户动作。`PetHost` 和 `NotificationPresenter` 实现同一呈现接口，因此关闭桌宠不会改变日志和重试逻辑。`WorkTracker` 只产生有效工作会话，不能访问窗口文本或输入内容。第二阶段 AI 模块通过皮肤生成接口接入，不改变上述核心模块。

## 4. 提醒行为

### 规则

每条规则包含名称、类型、启用开关、开始时间、结束时间、间隔、静默时段和最大重试次数。首批模板可提供“饮水”“起身活动”“休息眼睛”三个名称；间隔是软件配置项，不构成医疗建议，用户应根据医生后续意见修改。

### 状态机

```text
规则到期
  ├─ 锁屏/全屏/演示/静默时段 → 暂存或静默跳过
  └─ 普通桌面 → 桌宠提示（桌宠关闭则原生通知）
       ├─ 完成 → completed（接受）
       ├─ 稍后 → snoozed，默认十分钟后重提
       ├─ 跳过 → skipped（拒绝）
       └─ 无响应 → 十分钟后重提，三次后 unanswered
```

锁屏或全屏期间不显示桌宠和横幅；回到普通桌面后等待 2 分钟再提示。睡眠时段不生成睡眠记录，也不补发跨夜的过期提醒。每次动作都带计划时间、显示时间和动作时间，便于区分“没看到”和“明确跳过”。

### 渠道切换

桌宠开关为全局设置：开启时使用 C；关闭时使用 A。系统通知使用 Windows App SDK 的交互通知，点击动作直接回传提醒事件；不会把主窗口置前。用户可在托盘菜单中一键切换模式。

## 5. 工作时间统计

用户可维护白名单，例如 PyCharm、Visual Studio Code 或浏览器。每个应用规则保存进程标识和用户自定义显示名。

统计采样逻辑：

1. 周期性读取当前前台进程是否匹配白名单。
2. 检查 Windows 会话是否锁屏。
3. 检查系统空闲时间是否小于 5 分钟。
4. 三项同时满足时累计有效秒数；否则结束当前工作会话。
5. 应用退出、电脑锁定、切换到其他窗口或进入空闲状态时关闭会话。

数据库只保存应用配置的显示名、会话开始/结束时间和有效秒数，不保存窗口标题、项目名称、文件名、键盘内容或鼠标轨迹。主界面可按日、应用查看总有效时长。

## 6. 数据模型

核心表及字段如下：

```text
reminder_rules
  id, name, kind, enabled, start_local, end_local,
  interval_minutes, quiet_start, quiet_end, max_retries, created_at, updated_at

reminder_events
  id, rule_id, scheduled_at, displayed_at, channel,
  action, action_at, retry_index, suppressed_reason, created_at

tracked_apps
  id, process_name, display_name, enabled, created_at, updated_at

work_sessions
  id, tracked_app_id, started_at, ended_at, active_seconds, end_reason

app_settings
  key, value, updated_at
```

`action` 的允许值为 `completed`、`snoozed`、`skipped`、`unanswered`、`suppressed`。应用设置保存桌宠开关、当前皮肤 ID、托盘启动开关、主题和数据保留策略。默认不自动删除日志，由用户在设置中手动清理或导出。

## 7. 桌宠与皮肤系统

桌宠窗口采用无边框、透明背景、无任务栏按钮的 WPF 窗口。普通桌面默认显示在右下角，支持拖动、靠边停靠和大小调整；点击区域只覆盖角色和气泡，不拦截桌宠之外的鼠标操作。全屏、锁屏和演示状态自动隐藏，恢复后重新定位。

第一版皮肤包格式：

```text
skins/<skin-id>/
  manifest.json
  idle.png
  remind.png
  done.png       # 可选
  click.png      # 可选
  frames/        # 可选动画帧
```

`manifest.json` 至少包含 `id`、`name`、`version`、`author`、`license`、`canvasWidth`、`canvasHeight` 和 `fps`。所有图片要求包含 alpha 透明通道；导入时校验文件格式、尺寸、帧率和 manifest 字段，失败时不替换当前皮肤。

程序允许用户导入自己拥有或获授权的图片。开源仓库默认使用原创占位角色，不捆绑喜多郁代等第三方角色素材；个人用户可以在本地导入自己的皮肤。

## 8. 第二阶段 AI 工作室边界

第二阶段提供独立的“皮肤工作室”页面：选择本地参考图、填写外观和动作描述、预览生成结果、校验透明背景并导出标准皮肤包。应用通过 `IPetAssetGenerator` 接口调用在线图像服务，核心提醒器不依赖该接口。

实现约束：

- API 密钥保存在 Windows 凭据管理器或用户环境变量，不写入 SQLite、日志或 Git。
- 每次生成前显示网络、费用和图片上传提示；用户明确确认后才发送参考图。
- 生成失败、网络不可用或服务限额不会影响提醒和工作统计。
- 生成结果需经过尺寸、透明通道和 manifest 校验后才能设为当前皮肤。
- 使用个人角色图时由用户自行确认拥有使用权；公开发布的默认资产采用原创设计。

在 Codex 中，`imagegen` 适合生成或编辑桌宠位图、透明切图和动画素材；`brainstorming`、`writing-plans` 和后续实现技能负责需求、计划和代码流程。它们是开发工作流，不会作为运行时依赖嵌入 Ikuyo Pet；应用内 AI 需要单独的图像 API 或本地模型适配器。

## 9. 主界面与视觉方向

采用“清爽数据卡片”方向：浅色蓝粉主题、圆角卡片和清晰时间线。页面包括：

- 今日：当前提醒、饮水/活动完成数、有效工作时长。
- 时间线：按时间查看提醒渠道、动作和最终结果。
- 应用：白名单应用和每日有效工作时长。
- 桌宠：开关、当前皮肤、位置、大小、透明度和导入皮肤包。
- 设置：提醒规则、静默时段、托盘启动、数据导出和清理。

视觉主题与皮肤资源分离，换角色不会改变数据和业务逻辑。默认桌宠以轻气泡表达提醒，不持续播放声音，不弹出全屏窗口。

## 10. 安全、隐私与开源发布

- 默认离线运行；网络只在第二阶段 AI 工作室开启且经用户确认时使用。
- 采用最小权限，不要求管理员权限。
- 不把医疗报告作为输入或持久化数据；本软件不是医疗器械，也不替代医生意见。
- README 明确数据目录、导出方式、删除方式和第三方依赖许可证。
- 代码默认采用 MIT 许可证；第三方或用户导入的皮肤按各自许可证单独标注。
- CI 在 Windows runner 上执行构建、单元测试和发布包校验；不把本地数据库和用户皮肤纳入仓库。

## 11. 验收标准

第一版完成时必须满足：

1. 在没有 MySQL、网络和管理员权限的普通 Windows 账户下启动。
2. 应用关闭主窗口后仍可驻留托盘，并能创建提醒。
3. 默认桌宠为透明背景且可拖动；关闭桌宠后同一提醒改由原生通知呈现。
4. 通知或桌宠动作能一键写入完成、稍后或跳过结果。
5. 无响应按重试策略工作，日志能区分跳过与未响应。
6. 全屏和锁屏期间不出现桌宠或横幅，且不产生睡眠记录。
7. PyCharm 前台、未锁屏、系统空闲少于 5 分钟时累计有效时间；切换窗口或离开后停止累计。
8. 日志可按日期查看并导出，应用不保存窗口标题、文件名、输入内容或截图。
9. 本地皮肤包校验失败时保留当前皮肤；有效皮肤可无重启替换。
10. 核心单元测试覆盖提醒状态机、重试次数、静默条件和有效工作时长计算。

## 12. 进入实现前的固定决策

- 先实现离线核心，不提前加入 AI 生成依赖。
- 先提供原创占位皮肤，再导入个人角色素材。
- 默认桌宠 C，用户可切换原生通知 A。
- 默认记录提醒事件和有效工作会话，不记录睡眠。
- 所有提醒间隔、静默时段和白名单均可在界面修改，并由后续医嘱覆盖软件示例值。
