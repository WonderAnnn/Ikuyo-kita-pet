# Ikuyo Pet 提醒呈现与桌宠皮肤阶段规格

> 状态：已完成视觉方向确认，待书面审查。  
> 日期：2026-09-07

## 1. 阶段范围

本阶段实现第一版的提醒呈现路由、Windows 原生通知、透明可拖动桌宠和本地皮肤包替换。提醒状态机、SQLite 日志和前台应用统计沿用现有模块，不改变数据语义。

本阶段不实现应用内 AI 生成工作室，也不把 Codex skill 或在线图像服务作为运行时依赖。AI 工作室仍属于第二阶段。

## 2. 已确认的用户体验

| 项目 | 决定 |
| --- | --- |
| 默认渠道 | 桌宠优先（C）。关闭桌宠后自动切换到 Windows 通知（A）。 |
| 桌宠窗口 | 透明背景、可拖动、约 160 px，不抢键盘焦点，不弹全屏窗口。 |
| 提醒形态 | 语言气泡带小箭头，箭头指向桌宠本体。 |
| 动作样式 | 完成、延后、跳过嵌入同一句话；动作文字使用加粗和颜色，不使用按钮块或下划线。 |
| 文案语气 | 采用软软撒娇、活泼、亲切的语气；鼓励但不责备，不做医疗判断。 |
| 颜文字 | 每段最多 1 个，固定放在句尾；根据场景使用不同颜文字。 |
| 原生通知 | 复用同一提醒内容和动作语义；受 Windows 通知控件限制时使用系统动作按钮。 |
| 皮肤素材 | 支持用户导入自己拥有或获授权的素材；开源仓库不捆绑喜多郁代等第三方角色立绘。 |

### 2.1 文案与颜文字映射

底层动作仍使用稳定枚举，不因显示文案变化而改变日志：

| 场景 | 示例文案 | 颜文字 |
| --- | --- | --- |
| 提醒出现 | 「陪我起来走两分钟嘛～你愿意现在出发，还是让我等你一会儿？今天不方便的话，也可以先放过自己。」 | 不添加 |
| 用户完成 | 「太棒啦，活动完成！今天也有好好照顾自己呢」 | `ദ്ദി˶>𖥦<)✧` |
| 用户搁置 | 「好嘛，那我十分钟后再来找你，拜託嘛！」 | `(,,•́ . •̀,,)` |
| 用户跳过或达到重试上限 | 「这次没关系，我先安静陪着你；下次有空再一起动一动吧」 | `ʕ.•᷅ࡇ•᷄.ʔ` |

文案在资源或设置层可替换，代码只依赖动作 ID。公开版本使用原创、活泼的角色语气，不复制原作台词或官方文案。

## 3. 模块与数据流

```text
ReminderEngine
    │ ReminderDue（事件 ID、类型、显示文案、动作集合）
    ▼
ReminderPresentationRouter
    ├── PetReminderPresenter ──> 透明 PetWindow + 语言气泡
    └── WindowsNotificationPresenter ──> Windows App SDK 原生通知
                                      │
                                      ▼
                             ReminderActionDispatcher
                                      │
                                      ▼
                              IEventRepository（SQLite）
```

- `ReminderPresentationRouter` 只根据桌宠开关选择呈现渠道，不复制重试、日志或医疗规则。
- 两个 Presenter 共用同一个事件 ID 和动作处理器。点击完成、延后或跳过后，均只写入一次动作事件，并由状态机决定是否重试。
- 桌宠被锁屏、全屏或演示状态隐藏时，不创建可见横幅；恢复普通桌面并满足恢复延迟后再交给调度器处理。
- Presenter 发生初始化或渲染错误时，路由器降级到 Windows 通知；通知不可用时只记录受抑制原因，不打开主窗口抢焦点。

## 4. 透明桌宠设计

`PetWindow` 使用 WPF 实现，设置 `WindowStyle=None`、`AllowsTransparency=True`、`Background=Transparent`、`ShowInTaskbar=False`，并通过无激活窗口样式避免抢键盘焦点。

- 角色可见区域和气泡区域接收鼠标操作，透明区域不遮挡桌面。
- 拖动只改变窗口位置；位置和尺寸属于用户设置，不写入提醒事件。
- 气泡箭头使用独立的三角形元素指向角色，气泡不改变角色尺寸。
- 动作文字使用可聚焦的内联交互元素，视觉上无按钮边框；同时提供键盘焦点和可读名称。
- 默认角色尺寸约为 160 px；多显示器和 DPI 变化时重新约束到可见工作区。
- 锁屏、全屏和演示状态隐藏窗口；恢复后使用上次位置，不产生睡眠记录。

## 5. Windows 通知设计

`WindowsNotificationPresenter` 通过 Windows App SDK 的本地交互通知 API 发布提醒。通知激活参数至少包含事件 ID 和动作枚举，激活处理器只调用统一动作处理器，不主动打开主窗口。

- 通知文本复用 C 渠道的提醒内容；由于系统控件约束，A 渠道允许使用系统按钮呈现动作。
- 通知动作固定为完成、延后和跳过；延后默认使用现有规则的 10 分钟值，之后可由设置调整。
- 通知注册失败、权限不足或激活参数无效时记录可诊断错误，并保持桌宠渠道可用。
- 不使用声音循环、全屏窗口、窗口标题或通知之外的应用内容。

## 6. 皮肤包与替换

第一版皮肤包目录如下：

```text
skins/<skin-id>/
  manifest.json
  idle.png
  remind.png
  done.png       # 可选
  click.png      # 可选
  frames/        # 可选动画帧
```

`manifest.json` 至少包含 `id`、`name`、`version`、`author`、`license`、`canvasWidth`、`canvasHeight` 和 `fps`。必需图片必须存在 alpha 透明通道；尺寸、文件格式和帧率必须通过校验。

导入采用原子流程：

1. 复制到 `%LocalAppData%\IkuyoPet\skins\.staging\<guid>`。
2. 校验 manifest、图片、透明通道、尺寸和帧率。
3. 校验全部通过后移动到最终目录；相同 ID 不覆盖已有版本。
4. 更新当前皮肤设置并通知桌宠重新加载；失败时保留当前皮肤不变。

皮肤资源与视觉主题分离。替换角色不会改变提醒状态机、通知路由、SQLite 日志或工作时间统计。

## 7. 医嘱变化与配置兼容

医生后续给出确诊意见或建议后，可以调整提醒类型、间隔、静默时段、延后时间和活动提示文案。实现要求如下：

- 这些值存放在规则配置和用户设置中，不散落在 Presenter 或 WPF 界面代码里。
- 已产生的日志保持不可变；修改规则只影响之后产生的提醒。
- 软件不读取、解析或保存医疗报告，不根据报告自动推断疾病或给出治疗建议。
- 若医生建议暂时停止某类活动，用户可以禁用对应规则；桌宠、通知、日志和其他规则继续工作。
- 配置迁移必须保留用户已有设置；新增字段提供明确默认值并记录版本。

因此，后续医生建议可以改变“提醒什么、多久提醒、哪些时段静默”等数值，不需要推翻当前大方向或重建数据库。

## 8. 隐私与失败处理

- 日志只保存计划时间、显示时间、渠道、动作、动作时间、重试次数和结果。
- 不保存窗口标题、项目名称、文件名、键盘内容、鼠标轨迹、屏幕截图或睡眠时间。
- 用户导入的皮肤只存于本机用户目录，不自动进入 Git 或网络服务。
- 皮肤校验失败、通知不可用或桌宠渲染失败均不能破坏提醒日志和工作统计。

## 9. 测试与验收

### 自动化测试

- `ReminderPresentationRouterTests`：桌宠开关为真时路由到 `pet`，为假时路由到 `notification`。
- 通知动作测试：事件 ID 和动作参数可往返解析，三种动作进入统一处理器。
- `SkinPackageValidatorTests`：缺文件、manifest 字段缺失、尺寸越界、帧率不在 1–30、无 alpha 通道时拒绝导入并保留当前皮肤。
- 所有新增异步测试使用 `TestContext.Current.CancellationToken`，并运行 Core 与 Infrastructure 全量测试。

### 手工验收

- 桌宠显示在普通桌面右下角，透明背景、可拖动、约 160 px。
- 气泡箭头始终指向桌宠，句内动作文字可点击且不显示按钮块。
- 点击完成、延后、跳过各一次，日志分别记录正确结果；关闭桌宠后同一提醒由 Windows 通知呈现。
- 锁屏、全屏和演示状态不出现桌宠或横幅；恢复后按规则重新提醒。
- 导入有效透明皮肤可无重启替换；导入无效皮肤时当前皮肤不变。

## 10. 明确不在本阶段实现

- 应用内 AI 图片生成、联网图片上传、费用确认和 API 密钥管理。
- 喜多郁代或其他第三方官方素材的默认打包。
- 云同步、账号体系、远程推送和睡眠记录。
