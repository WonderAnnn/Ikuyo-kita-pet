# 卸载程序与单条通知设计

## 背景

Ikuyo Pet 目前以 `artifacts/publish/latest` 作为便携式发布目录，并通过桌面快捷方式启动。程序运行数据保存在 `%LOCALAPPDATA%\\IkuyoPet`。当前 Windows App Notification 使用事件 ID 作为 Tag，连续提醒会积累为多条待处理通知；用户隐藏桌宠时需要逐条点击处理。

本次改动解决两个问题：

1. 提供能随发布包使用的卸载程序，并在卸载时让用户选择是否保留设置、日志和备份。
2. 桌宠隐藏时只保留一条 Windows 提醒，后来的提醒替换旧提醒；桌宠显示时继续使用现有气泡反馈。

## 已确认的用户决策

- 卸载数据策略采用“卸载时选择”：
  - **保留数据并卸载**：删除程序文件、快捷方式和发布目录，保留 `%LOCALAPPDATA%\\IkuyoPet`。
  - **删除数据并卸载**：在上述基础上删除 `%LOCALAPPDATA%\\IkuyoPet`。
  - **取消**：不做任何修改。
- 卸载图标采用项目原创素材目录中的 `assets/branding/icon/icon256.ico`；其余尺寸图标继续作为公开资源保留。
- 通知策略采用“最新替换旧通知”，不采用静默丢弃新提醒。

## 方案

### 1. 内置卸载程序

新增 `src/IkuyoPet.Uninstaller` Windows 可执行项目，发布为 `IkuyoPet.Uninstaller.exe`，并由发布脚本复制到 `artifacts/publish/latest`。程序使用与主程序一致的原创 `icon256.ico`。

卸载程序流程：

1. 从自身位置定位发布根目录；只接受同时包含 `IkuyoPet.exe` 和 `build-info.json` 的目录，拒绝源码目录、仓库根目录和未验证路径。
2. 如果检测到 `IkuyoPet.exe` 正在运行，提示先退出并提供重试/取消，不强制杀进程。
3. 显示三个明确选项：保留数据、删除数据、取消。
4. 记录最小化的卸载诊断（目标目录、版本、选择、失败原因），不把用户数据内容写入日志。
5. 为避免程序删除自身失败，将发布根目录的顶层运行时文件复制到临时目录并启动 helper；helper 等待卸载程序退出后删除发布目录，并按选择删除数据目录。临时复制不增加发布包体积。
6. 删除由发布脚本维护的桌面快捷方式；快捷方式目标不是当前发布目录时不删除，避免误删用户手工创建的同名快捷方式。
7. 删除失败时保留可恢复状态，弹窗说明具体路径和重试方式，不删除用户数据（除非数据删除已经成功完成）。

卸载程序不负责删除源代码、`local-assets`、`local-skins`、其他版本发布目录或用户指定的外部目录。

### 2. 单条 Windows 通知

在 `WindowsAppNotificationSink` 外增加可测试的单条通知协调层，使用固定的逻辑 Tag/Group（例如 `ikuyo-pet-reminder`）：

1. 每次显示前移除相同 Tag/Group 的现有通知，再提交最新通知。
2. 最新通知保留完整的事件 ID 和操作按钮；点击完成、稍后提醒或跳过后清理该 Tag/Group。
3. 同一进程内通过异步锁串行化“移除→显示”，避免并发提醒产生两条通知。
4. Windows App Notification 不可用时继续走现有托盘回退，并由同一协调层保证最多一个待处理回退提醒。
5. 桌宠可见时不改变 `ReminderPresentationRouter` 的气泡路径；“单条通知”只约束隐藏桌宠的通知路径。
6. 应用重启后不依赖内存中的事件列表；启动时先清理固定 Tag/Group 的残留提醒，再允许新提醒进入。

如果当前 Windows App SDK 版本不提供按 Tag/Group 删除接口，协调层将使用该 SDK 支持的等价更新/移除 API；不会通过无限制的内存队列模拟通知。

## 发布集成

- `IkuyoPet.Uninstaller.exe` 加入发布项目和 `scripts/publish-latest.ps1` 的资源完整性校验。
- `build-info.json` 增加卸载程序文件哈希/版本信息。
- `artifacts/publish/latest` 仍是唯一桌面快捷方式目标；卸载程序从该目录运行时只清理该发布目录。
- 压缩包包含主程序、公开 `assets`、`build-info.json` 和卸载程序，解压后可直接使用。
- 不解除 `local-assets/`、`local-skins/`、`tmp/` 等私有/临时目录的 Git 忽略规则。

## 测试策略（先写测试，再实现）

### 卸载程序

- 目标目录校验：合法发布目录可识别，仓库根目录、缺少标记文件的目录、路径穿越均拒绝。
- 三种选择：取消不改动；保留数据只删除程序/快捷方式；删除数据额外删除 `%LOCALAPPDATA%\\IkuyoPet`。
- 运行中进程：第一次检测失败不会删除文件，退出后重试成功。
- 快捷方式安全：只删除目标指向当前发布目录的快捷方式。
- 删除失败：显示错误且不会误删未完成的目标。
- 发布契约：`latest` 中存在卸载程序，文件哈希记录在 `build-info.json`。

### 通知

- 隐藏桌宠连续触发 2、5、20 条提醒，底层通知 API 的待处理数量始终为 1，内容为最后一条。
- 并发触发时移除/显示操作不交错，固定 Tag/Group 不变化。
- 点击每个操作后清理该条通知，事件 ID 仍能正确路由到 `ReminderActionCoordinator`。
- 桌宠可见时仍只显示气泡，不调用 Windows 通知协调层。
- 重启初始化会清理旧 Tag/Group；通知 API 失败时托盘回退仍最多一条。

## 验收标准

- 从 `latest` 双击卸载程序可以完成三种选择，且不会删除源码或其他发布版本。
- “隐藏桌宠 + 连续提醒”场景下 Windows 待处理通知数量最大为 1。
- 原有提醒动作、手动喝水/休息、日志记录、桌宠气泡行为不回归。
- `dotnet build`、`dotnet test`、发布脚本和资源校验全部通过，压缩包可在全新目录运行。

## 非目标

- 本次不引入 MSI/WiX、注册表安装项或自动更新服务。
- 本次不改变提醒规则、间隔计算或 UI 主题，只改卸载生命周期和隐藏状态下的通知聚合。
