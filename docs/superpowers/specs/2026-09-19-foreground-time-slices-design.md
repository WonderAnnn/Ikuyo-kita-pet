# 前台切屏时间片追踪设计

## 目标

在多个白名单软件之间快速切换时，按实际前台切换时间记录有效工作时长，避免仅依赖 30 秒轮询造成漏记、误记或错误归属。

## 方案

采用 Windows 前台窗口事件 `EVENT_SYSTEM_FOREGROUND` 作为主时间线，并保留 30 秒轮询作为校正和锁屏/空闲状态检查。事件监视器只负责捕获新鲜的 `ActivitySample`，工作追踪服务继续负责白名单、锁屏、全屏、演示模式和空闲阈值判断。

每次前台事件样本都会在工作追踪服务中结束上一段时间片并开始当前应用时间片。事件触发后已写入数据库的时间，不再由主界面的“未落库实时秒数”重复叠加；提醒调度仍消费同一份 `ActiveWorkDelta`。事件来源通过接口抽象，测试使用内存事件源，不依赖真实 Windows 钩子。

## 数据流

1. `WindowsForegroundActivityChangeSource` 在后台消息线程安装 WinEventHook。
2. 前台变化时使用未缓存的 `ForegroundActivityProbe` 捕获样本，并写入事件队列。
3. `WorkTrackingLoop` 串行消费事件样本；定时轮询仍调用同一服务进行校正。
4. `WorkTrackingService` 按样本时间切分会话，并返回包含“是否已落库”的增量。
5. 提醒循环始终消费增量；主界面只对未落库增量保留实时缓存。

## 边界和回退

- WinEventHook 安装失败时不阻止应用启动，现有轮询继续工作。
- 事件样本仍通过已有白名单、锁屏、全屏、演示和 5 分钟空闲规则过滤。
- 跨午夜按时间戳由现有统计查询拆分到本地日期。
- 关闭工作追踪循环时先停止事件源，再刷新最后一个会话。

## 测试标准

- 快速 A→B→A 样本分别生成对应秒数的会话，不把整个轮询间隔归给一个应用。
- 前台切换已落库的增量不会在主界面再次累加。
- 事件源失败时轮询回退仍能累计工作。
- 现有工作追踪、提醒、统计和完整解决方案测试全部通过。
