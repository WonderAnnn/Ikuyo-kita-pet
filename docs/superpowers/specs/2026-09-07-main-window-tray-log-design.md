# Ikuyo Pet 主窗口、托盘与日志界面规格

> 状态：已完成交互方向讨论，待用户审阅规格后进入实现计划。  
> 日期：2026-09-07

## 1. 目标与边界

本规格定义第一阶段主窗口、系统托盘和日志页面的交互与视觉结构。它与已完成的提醒呈现路由、Windows 通知、透明可拖动桌宠和皮肤替换保持一致。

第一阶段继续保持完全离线运行：SQLite 为本机数据存储，不需要 MySQL 或其他数据库服务；桌宠资源可以由用户本地替换。应用内 AI 生成工作室、联网图片上传和云同步留到第二阶段。

不记录睡眠时间，不读取或解析医疗报告，也不根据检查结果自动调整健康建议。医生后续给出的建议只通过设置中的规则、间隔、静默时段和文案配置影响之后的提醒。

## 2. 已确认的交互选择

| 区域 | 已确认方案 | 设计含义 |
| --- | --- | --- |
| 主窗口默认入口 | A · 今日优先 | 打开软件先看今天的状态、下一次提醒和桌宠陪伴卡 |
| 首屏主卡 | A1a · 一句话陪伴 | 桌宠 + 下一次提醒为主，统计压缩为小摘要 |
| 系统托盘 | T1 · 极简托盘 | 只管理桌宠显示、暂停、打开今日和退出，不重复堆叠记录动作 |
| 日志页面 | L1 · 今日时间线 | 按日期分组显示时间、活动、渠道、动作和结果 |

## 3. 主窗口结构

```text
┌─────────────────────────────────────────────────────┐
│  Ikuyo Pet                         最小化 关闭       │
├──────────────┬──────────────────────────────────────┤
│ 今日         │ 早上好，今天也慢慢来                  │
│ 日志         │ [桌宠陪伴卡：角色 / 下一次提醒 / 气泡] │
│ 提醒规则     │ [喝水摘要] [活动摘要] [工作摘要]       │
│ 桌宠与皮肤   │ 今日提醒时间线摘要                      │
│ 设置         │                                      │
└──────────────┴──────────────────────────────────────┘
```

- 左侧导航保持稳定，不因桌宠隐藏而消失：今日、日志、提醒规则、桌宠与皮肤、设置。
- A1a 首卡中桌宠和下一次提醒占主要视觉面积；完成数、活动数和工作时长是小型摘要，不使用高密度图表。
- 卡片中的工作时长只显示符合以下条件的累计值：白名单应用位于前台、电脑未锁屏、最近 5 分钟有人机操作。后台运行、锁屏、离开电脑不计时。
- 首屏不显示睡眠指标，不展示医疗诊断或身体评分。
- 点击日志摘要进入 L1 时间线；点击规则或皮肤进入对应设置页面。

## 4. 桌宠与首卡协作

- 桌宠仍是透明背景、可拖动、约 160 px、无任务栏图标、不抢键盘焦点的独立窗口。
- 首卡不复制一个完整桌宠窗口，而是显示当前皮肤预览、桌宠可见状态和下一次提醒摘要。
- 提醒出现时，桌宠气泡显示一段自然语言；完成、延后、跳过作为句内加粗文字选项，不使用传统按钮块。
- 每段文案最多使用一个颜文字，并放在句尾；完成、搁置、跳过等场景使用不同颜文字。
- 桌宠被关闭时，路由自动切换到 Windows 原生通知；重新开启后恢复桌宠渠道。

## 5. T1 极简托盘

托盘右键菜单固定为四项，顺序如下：

1. 显示 / 隐藏桌宠
2. 暂停提醒 30 分钟
3. 打开今日
4. 退出 Ikuyo Pet

约束：

- 托盘不显示统计数字、工作计时或长日志，避免后台常驻变成仪表盘。
- 托盘不重复提供“喝水了 / 活动了”等记录动作；这些动作只在桌宠气泡或 Windows 通知中出现。
- 选择“打开今日”只激活主窗口，不创建额外提醒，不改变日志。
- 暂停状态在托盘菜单中显示剩余时间；到期后恢复调度器。
- 启动项、桌宠开关、默认皮肤等长期设置放在设置页，不塞进托盘菜单。

## 6. L1 今日时间线日志

### 6.1 列表内容

每条时间线记录至少包括：

- 日期与显示时间
- 活动类型（喝水、起身活动、自定义规则）
- 提醒渠道（桌宠或 Windows 通知）
- 用户动作（完成、延后、跳过、未响应）
- 动作发生时间、重试次数
- 可选的简短反馈语句或颜文字

工作统计记录继续遵守白名单前台、未锁屏、近 5 分钟有人机操作的约束；日志只显示汇总，不保存窗口标题、项目名、文件名、键盘内容、鼠标轨迹或屏幕截图。

### 6.2 阅读方式

- 默认打开“今天”时间线，按日期分组，最新记录在上方。
- 顶部提供日期切换和轻量筛选：全部、喝水、活动、工作统计，以及完成、延后、跳过。
- 颜色用于区分结果但不能只依赖颜色：完成、延后、跳过均同时显示文字。
- 空状态使用温和的角色语气，不责备用户；没有记录时提示“今天还没有小记，等下一次提醒再一起记录吧”。
- 日志数据使用现有 SQLite 仓储；界面不直接修改历史记录，医生建议变化只影响未来提醒。

## 7. 数据与兼容性

- 所有正式数据均保存在本机 SQLite 文件，不要求安装或运行 MySQL。
- 主窗口、托盘和日志只调用现有应用服务、提醒状态机和事件仓储，不复制业务规则。
- 规则间隔、静默时段、延后时间、白名单应用和桌宠开关均来自配置层；不得硬编码在 WPF 视图。
- 日志事件保持不可变；配置迁移保留既有记录和用户设置，新字段提供明确默认值。

## 8. 验收重点

### 自动化

- 主窗口导航能打开今日、日志、规则、皮肤和设置页面。
- T1 托盘四项命令调用正确服务；显示 / 隐藏和暂停不会写入提醒动作日志。
- L1 时间线按日期排序，完整显示时间、活动和完成 / 延后 / 跳过结果。
- 工作时长只在白名单前台、未锁屏且近 5 分钟有输入时累计。
- UI 层不产生睡眠记录，不访问医疗报告内容。

### 手工

- 启动应用后默认进入 A1a；桌宠仍可单独拖动和隐藏。
- T1 托盘保持短菜单，主窗口从“打开今日”恢复到前台。
- 完成、延后、跳过提醒后，L1 时间线立即显示对应结果；重复重试不会产生重复事件。
- 关闭桌宠后同一提醒通过 Windows 通知呈现；重新打开后恢复桌宠优先。
- SQLite 文件可随应用一起运行，换一台没有 MySQL 的 Windows 电脑仍可启动（只需应用自身运行时）。

## 9. 明确不在本规格

- 应用内 AI 图片生成工作室和二次元图片识别。
- 默认捆绑喜多郁代等第三方角色素材；公开版本只提供空白 / 原创示例皮肤和用户自带素材导入。
- 云端账号、远程推送、睡眠时间和医疗诊断建议。
